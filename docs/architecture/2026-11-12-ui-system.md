> 业务流程：[各阶段完整工作流](./2026-11-08-stage-workflows.md)

## 1. 范围与原则

UI 系统服务于两个运行环境：

- Studio：角色创作、Live2D 产线、模型管理、Agent 与设置。
- Pet：透明桌宠窗口、聊天气泡、审批提示和少量弹层。

目标不是建立一套通用 SaaS 后台，而是建立适合“角色创作工作台”的稳定视觉和交互底座：

1. 画面安静，内容优先。背景、边框和状态色不能抢过立绘、图层和模型预览。
2. 用户始终知道当前阶段、当前版本和下一步动作。
3. 候选、草稿、正式版本和已发布内容不能只靠颜色区分。
4. 长任务期间保留页面上下文，不用全屏加载页替换用户正在编辑的内容。
5. 通用组件不包含角色、版本、Prompt、Live2D 或 Agent 领域语义。
6. Studio 与 Pet 共用 token 和基础组件，不各自复制一套按钮、输入框或浮层。

首版是单用户本地工作台，不设计登录页、账号菜单、成员管理、组织切换、共享权限或 RBAC。设置页只管理当前本地工作区的偏好、Provider 连接、Agent 权限和本地数据；`本地会话已失效` 文案指 sidecar token 失效，不是用户退出登录。未来账号系统应在外层增加工作区/账户页面，不改变 design-system 的组件边界。

### 1.1 UI 信息边界

默认界面只展示用户做判断和操作所需的信息：

| 展示等级 | 内容                                                                       | 默认位置                                |
| -------- | -------------------------------------------------------------------------- | --------------------------------------- |
| 常驻     | 当前阶段、可读版本名、active/candidate 状态、来源摘要、阻塞项、主要动作    | 页面标题、阶段轨道、Inspector、操作条   |
| 按需展开 | 本次修改、影响范围、参考图、质量警告、工具调用摘要、支持码                 | 侧栏、折叠区、详情页                    |
| 高级详情 | 变更明细、参数差异、构建诊断、审批记录                                     | `TechnicalDetailsDisclosure` 或诊断弹层 |
| 内部保留 | 数据库 ID、内容 hash、CAS、Schema hash、Job checkpoint、审计事件、原始事件 | 不进入默认 UI                           |

内部字段仍然必须持久化，但由领域层、服务层和审计页消费。通用组件不能要求调用方传入这些字段。

## 2. 包边界

### 2.1 `packages/design-system`

包名：`@agent2live/design-system`

职责：

- 设计 token、全局样式和主题入口。
- 无业务语义的 React 组件、交互行为和无障碍约定。
- 通用布局原语、反馈态、浮层、导航和数据显示原语。
- 组件画廊、状态矩阵和视觉回归基线。

不负责：

- 请求、SSE、缓存、持久化或路由。
- `ArtVersion`、`PromptVersion`、`ModelBuild` 等领域类型。
- 当前角色、当前项目、任务或审批状态。
- 业务文案拼接、状态中文映射或权限判断。
- Cubism、PixiJS、PSD 解析或任何渲染运行时。

依赖约束：

- `react`、`react-dom` 作为 peer dependency。
- 不依赖 `react-router-dom`、TanStack Query、Zustand、Electron API 或 `@agent2live/contracts`。
- 复杂浮层可使用内部 headless primitive，但不得把第三方组件的非稳定 API 暴露为公共 API。
- 默认使用 CSS Custom Properties、CSS Modules 和 React 18。
- 只允许通过 `@agent2live/design-system` 和显式样式入口导入，不允许深路径导入。

### 2.2 应用层

以下内容留在 `apps/desktop`：

- `StudioAppShell`、`PetShell` 等与路由、窗口和 SSE 生命周期绑定的外壳。
- `PromptBlockCard`、`ReferenceChainBar`、`CandidateCompareView`、`PsdLayerTree`、`RigViewport`、`ModelQcPanel`、`AgentTaskCard` 等业务组合。
- 领域状态到用户文案、图标和视觉 tone 的映射。
- 数据查询、命令提交、权限判断和任务订阅。

业务组合必须先由 design-system 的组件组成，不允许在页面中重新实现按钮、输入框、弹层和状态标签。

### 3.1 包清单与构建

包清单至少满足以下契约：

```json
{
  "name": "@agent2live/design-system",
  "private": true,
  "type": "module",
  "sideEffects": ["**/*.css"],
  "exports": {
    ".": {
      "types": "./dist/index.d.ts",
      "import": "./dist/index.js"
    },
    "./styles.css": "./dist/styles.css"
  },
  "peerDependencies": {
    "react": "^18.3.1",
    "react-dom": "^18.3.1"
  }
}
```

- JavaScript 和类型产物由 Vite library mode 与 TypeScript declaration build 生成。
- CSS Modules 在构建时收敛为包内稳定类名，组件库公共 API 不暴露内部类名。
- `styles.css` 是唯一样式入口；`tokens.css` 可以作为诊断入口存在，但业务页面不能依赖深路径。
- 包内不得包含许可证不明确的图标、图片或字体；业务图标由应用层通过 `ReactNode` 传入。

## 4. 设计基线

以下值来自当前设计稿的主页面、操作按钮、选中行、提示块和工作台卡片。它们是 token 的实施基线，业务页面不得重复写十六进制颜色或任意圆角。

### 4.1 核心颜色

| Token                          | 基线值    | 用途                        |
| ------------------------------ | --------- | --------------------------- |
| `--a2l-color-app-bg`           | `#F8FAF9` | Studio 页面和工作区背景     |
| `--a2l-color-surface`          | `#FFFFFF` | 面板、导航、Inspector、侧栏 |
| `--a2l-color-surface-subtle`   | `#F8FAF9` | 嵌套卡片、输入区、轻量分区  |
| `--a2l-color-surface-selected` | `#EFFAF7` | 当前图层、当前步骤、已选行  |
| `--a2l-color-accent`           | `#3FB0A0` | 主按钮、当前状态、进度      |
| `--a2l-color-accent-strong`    | `#2E9183` | 强调文字、成功状态          |
| `--a2l-color-accent-soft`      | `#EAF7F4` | 强调背景、轻提示            |
| `--a2l-color-text`             | `#252A32` | 标题和主要正文              |
| `--a2l-color-text-secondary`   | `#3C434E` | 次级数据、正文              |
| `--a2l-color-text-muted`       | `#A8AEB8` | 说明、占位、元信息          |
| `--a2l-color-border`           | `#E7ECEA` | 面板和卡片边界              |
| `--a2l-color-border-strong`    | `#E2E6E5` | 控件边界                    |
| `--a2l-color-warning-bg`       | `#FDF5E9` | 待确认、缺失项提示          |
| `--a2l-color-warning`          | `#B07C33` | 警告文字和图标              |
| `--a2l-color-danger`           | `#A85468` | 危险状态文字和图标          |
| `--a2l-color-danger-border`    | `#EFD8D3` | 危险操作的克制边界          |
| `--a2l-color-focus`            | `#3FB0A0` | 键盘焦点环                  |

补充约束：

- 主强调色不能用于整页背景。
- 危险色只表达不可逆操作、删除和阻塞状态，不表达普通错误标题。
- 当前选中的导航、图层或步骤必须有文字、图标或 `aria-current` 辅助，不能只换背景色。
- Pet 聊天气泡背景可以使用 `--a2l-pet-gradient`：`linear-gradient(135deg, #EBF6F2 0%, #F0F5FA 27.5%, #FCF0F5 50%)`。该 token 只在 Pet 主题启用。

v1 交付 `studio-light` 和 `pet-light`。token 结构预留主题切换，但深色主题在专门设计稿完成前不作为发布门槛。

### 4.2 字体

当前设计使用 `Noto Sans SC`。技术实现统一为：

```css
--a2l-font-sans: 'Noto Sans SC', 'PingFang SC', 'Microsoft YaHei', sans-serif;
--a2l-font-mono: 'SFMono-Regular', 'Cascadia Code', monospace;
```

| Token           | 字号 / 行高 | 字重 | 用途               |
| --------------- | ----------- | ---- | ------------------ |
| `text-caption`  | 10.5 / 14   | 400  | 时间、辅助说明     |
| `text-meta`     | 11.5 / 16   | 400  | 参数名、表格元信息 |
| `text-body-sm`  | 12 / 18     | 400  | 列表和表单正文     |
| `text-body`     | 13 / 20     | 400  | 主要正文           |
| `text-label`    | 12 / 18     | 500  | 字段名、按钮、标签 |
| `text-title-sm` | 14 / 20     | 500  | 面板标题、卡片标题 |
| `text-title`    | 18 / 26     | 500  | 页面区块标题       |
| `text-display`  | 24 / 32     | 500  | 页面主标题         |

字体文件随应用本地打包，不从网络加载。数字和参数值使用 tabular figures，避免进度和参数变化时抖动。

### 4.3 间距、圆角和描边

基础间距使用 2px 步进，业务布局优先使用语义别名：

```css
--a2l-space-1: 4px;
--a2l-space-2: 8px;
--a2l-space-3: 12px;
--a2l-space-4: 16px;
--a2l-space-5: 20px;
--a2l-space-6: 24px;
--a2l-space-7: 28px;
--a2l-space-8: 32px;
--a2l-space-10: 40px;
--a2l-space-14: 56px;
```

圆角：

- `radius-xs`: 6px，用于小标签。
- `radius-sm`: 8px，用于列表选中行。
- `radius-md`: 10px，用于输入框和小按钮。
- `radius-control`: 11px，用于 42px 主按钮。
- `radius-lg`: 14px，用于卡片和面板。
- `radius-xl`: 18–20px，用于页面级容器和全屏弹层。

描边默认为 1px。Studio 的层级主要通过背景、间距和边界表达，阴影只用于真正浮在主画布上方的菜单、Dialog 和 Toast。

### 4.4 动效

| Token             | 值                           | 用途                         |
| ----------------- | ---------------------------- | ---------------------------- |
| `motion-fast`     | 120ms                        | Hover、按压、聚焦            |
| `motion-base`     | 180ms                        | 展开、Tab、轻量状态切换      |
| `motion-emphasis` | 240ms                        | Dialog、Drawer、页面状态进入 |
| `ease-standard`   | `cubic-bezier(0.2, 0, 0, 1)` | 默认缓动                     |

不得通过持续动画表达长任务。进度、重试和任务状态必须来自真实状态；`prefers-reduced-motion: reduce` 时只保留透明度变化。

## 6. 通用组件与业务组件

以下内容不应进入 `packages/design-system`：

| 应用层组件                            | 原因                               |
| ------------------------------------- | ---------------------------------- |
| `CharacterCard`                       | 依赖角色数据和路由                 |
| `PromptBlockCard`                     | 依赖 PromptBlock、锁定和示例引用   |
| `MaterialTray`                        | 依赖素材角色、上传和内容寻址资产   |
| `CandidateCompareView`                | 依赖生成候选和采纳冲突             |
| `VersionGraph` / `ProjectLineageTree` | 依赖版本 DAG 和 Fork 领域          |
| `PsdLayerTree`                        | 依赖 PSD 图层语义和角色校验        |
| `RigViewport`                         | 依赖 Live2D Runtime 和交互选区     |
| `ModelQcPanel`                        | 依赖 QC 报告和发布权限             |
| `MemoryItemCard`                      | 依赖记忆来源和删除规则             |
| `AgentTaskCard`                       | 依赖 Agent session、审批和任务投影 |
| `ToolPermissionTable`                 | 依赖工具授权策略和风险分类         |

这些组件应当只组合 `SurfaceCard`、`StatusPill`、`KeyValueList`、`Tabs`、`Dialog`、`Button` 等通用原语。

## 7. 页面壳与工作台布局

### 7.1 Studio

当前设计采用两层导航：

```text
┌──────┬──────────────┬──────────────────────┬──────────────┐
│ 64px │ 220/240px    │ 弹性主画布             │ 320px        │
│ 全局 │ 页面上下文     │ 预览/图层/候选/参数     │ Inspector    │
│ 导航 │ 版本/图层/任务 │                      │ 属性/报告/历史 │
├──────┴──────────────┴──────────────────────┴──────────────┤
│ 58px 操作条：状态摘要 | 次级操作 | 当前主操作                │
└───────────────────────────────────────────────────────────┘
```

约束：

- 全局导航固定 64px，窄窗口可只显示图标。
- 上下文栏按页面使用 220px 或 240px；用户可折叠。
- Inspector 默认 320px，可拖动；窄窗口变为 Drawer。
- 顶栏 56–60px，内容区以圆角或边框分隔，不使用厚重阴影。
- 主画布最小宽度不足时，优先折叠 Inspector，再折叠上下文栏。
- 长任务期间主画布、候选选择和未保存表单保持挂载。
- `StageRail` 放在顶栏或主画布上方，不替换页面标题。

### 7.2 Pet

Pet 不使用 Studio 全宽工作台：

- 透明窗口只承载角色、气泡和必要的审批小面板。
- 输入框、按钮和状态提示复用 design-system。
- `Transcript`、`Memory`、`Task center` 打开 Studio 路由，不在透明窗口中塞入完整管理页。
- 模式切换共享视觉，但 Direct、Forward、Agent 的边界说明和状态反馈由应用层提供。

## 8. 组件合同

### 8.1 公共 API

- 所有可交互组件支持 `disabled`；异步动作额外支持 `busy`。
- 受控和非受控表单组件遵循同一命名：`value/defaultValue/onValueChange`。
- DOM 透传 props 使用 `...rest`，不能吞掉 `aria-*`、`data-*`、`title` 和事件。
- 需要 DOM 引用的组件使用 `forwardRef`。
- 图标和操作扩展使用 `ReactNode` 插槽，不在 token 包中固定业务图标。
- `className` 只用于布局扩展；页面不能借助它重写核心颜色、圆角或交互状态。
- 视觉状态同时输出 `data-state`，便于样式、测试和调试。
- 文案由应用层传入；组件不内置不可覆盖的业务中文。

### 8.2 事件

- 点击提交类动作只发出一次受控回调。
- `busy` 时默认禁止重复动作，但允许调用方显式选择可取消的实现。
- Dialog、Drawer 和 Popover 必须恢复到触发元素焦点。
- Escape 关闭浮层的行为可由调用方关闭，但默认开启。

### 8.3 样式入口

```ts
import '@agent2live/design-system/styles.css'
import { Button, StatusPill, WorkbenchLayout } from '@agent2live/design-system'
```

`styles.css` 只包含 reset、token、theme 和组件基础样式。业务样式放在应用层，但只能消费 token。

## 9. 无障碍

- 目标为 WCAG 2.2 AA。
- 键盘可完成所有非 Canvas 操作；Canvas 相关组件必须提供等效参数面板或列表。
- 焦点环不能移除，颜色使用 `--a2l-color-focus`，并与背景保持可见对比。
- 普通文字和背景达到 4.5:1；大字号和图形边界达到 3:1。
- 状态不能用颜色作为唯一区分，必须配合文字、图标或 `aria-current`。
- Toast 不是唯一反馈渠道；阻塞错误必须留在页面结构中。
- 异步任务使用合适的 `aria-live`，避免每秒播报进度。
- 所有图标按钮必须有可访问名称。
- 最小可点击高度：桌面紧凑控件 32px，主要操作 40px；关键审批和危险操作不得小于 40px。

## 10. 测试与组件画廊

每个公开组件至少包含：

- 默认、hover、focus、disabled 和错误状态故事。
- 键盘交互测试。
- 受控/非受控行为测试。
- `aria` 角色和名称断言。
- 1440×900 下的视觉快照。
- `prefers-reduced-motion` 快照。

组件画廊使用 Storybook 或等价的 Vite 组件页，作为设计交接和视觉验收入口。复杂业务组件不要求进入画廊，但必须使用同一批基础组件。

CI 至少包含：

| 检查       | 内容                                                 |
| ---------- | ---------------------------------------------------- |
| Typecheck  | 公共导出和 props 类型                                |
| Unit       | 交互、键盘、受控状态、焦点恢复                       |
| A11y       | axe 或等价自动检查，人工键盘抽检                     |
| Visual     | 核心组件在 1x/2x 下的截图对比                        |
| Token lint | 业务代码不得出现未登记的十六进制颜色、阴影和圆角常量 |
| Bundle     | Studio 与 Pet 不重复打入完整组件库                   |

视觉回归允许字体抗锯齿的微小差异，不允许布局位移、裁切、焦点丢失或颜色 token 漂移。

## 11. 发布与演进

- `packages/design-system` 是 workspace 内部包，默认不独立发布到公共 registry。
- 公共导出遵循 semver；删除或重命名导出必须提供迁移说明。
- token 变化先更新画廊和快照，再迁移业务页面。
- 页面不得临时复制组件；缺失能力先补组件规格和测试，再由页面使用。
- 业务页面需要特殊视觉时，优先增加语义 token 或插槽，不直接覆盖组件内部 class。
- 每次设计稿更新，先核对 token、组件尺寸、状态矩阵和焦点行为，再更新业务页面。

## 12. 首批实现顺序

1. tokens、reset、themes 和 `Button`、`IconButton`、`AsyncButton`。
2. `Field`、`TextField`、`Textarea`、`Select`、`Switch`、`SearchField`。
3. `SurfaceCard`、`StatusPill`、`CountBadge`、`ProgressBar`、`EmptyState`、`ErrorState`。
4. `PageHeader`、`Toolbar`、`ActionBar`、`ScrollArea`、`WorkbenchLayout`、`StageRail`。
5. `Tabs`、`Accordion`、`Disclosure`、`Tooltip`、`Popover`、`Dialog`、`ConfirmDialog`、`Drawer`。

先迁移已有 `StatusPill`、`AsyncButton`、`EmptyState`、`ConfirmDialog` 和 `ErrorState`。`StudioAppShell` 因依赖路由和 SSE，继续留在应用层，但内部导航、按钮和状态展示必须使用通用组件。
